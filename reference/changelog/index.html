Release Changelog¶

0.9.4 (2026-11-08) - @Pratap-kute¶

Accounting and calculation fixes¶

  • Capital gains tax: grandfathering now applies to long term equity only and uses the higher of the actual cost and the lower of the 31 Jan 2018 price and the sale price, so it can no longer create or inflate a loss. A missing price keeps the actual cost (#23).
  • Capital gains tax: long term equity gains are exempt only for sales before 1 Apr 2018, equity rates follow the sale date (20% short term and 12.5% long term from 23 Jul 2024), and debt units bought on or after 1 Apr 2023 are no longer indexed (#23).
  • Capital Gains yearly totals add up all accounts. A year with a net loss owes no tax (#23, #25).
  • Asset Balance, Gain and Net Worth use one event based accounting. Cash (checking) accounts report their balance but no gain or XIRR, and a group's gain covers its investment accounts only (#23).
  • Asset Balance labels the gain column "Investment Change" and adds a Cash column (cashAmount computed in the backend), so a group's market value splits into investments plus cash (#29).
  • Asset Balance, Allocation and Goals count postings up to today. Future-dated postings are no longer included (#23).
  • The backend now calculates per-posting unrealized gain, holding days and compound annualized return (shown only for lots held a year or more), goal analysis (required contribution, projected completion, schedule status) and the dashboard expense pace. The frontend no longer recomputes them (#23, #25).
  • Demo data: the last home loan payment is capped at the balance owed (#23).

UI and UX¶

  • Added a collapsible desktop sidebar that collapses to a 4rem icon rail with tooltips, expands group menus on click, persists state in localStorage, and dynamically adjusts wide-screen analysis layouts (#30).
  • Transactions show debits and credits in two columns, with account icons rendered correctly. Postings render as one record per row on phones (#23).
  • Returns (XIRR, APR, annualized) are percentages, shares and progress use one decimal, and the default currency has no suffix (#23).
  • Financial year pickers default to the latest year with data, so yearly pages no longer open blank (#23).
  • Loading and empty states explain the reason and the next step. An in-app confirmation dialog replaces browser confirm() for refresh, template deletion, config reset and unsaved changes (#23).
  • Commodities & Prices show the provider's commodity type and ID instead of "unknown" when the newest price comes from a ledger P directive (#29).
  • Command Palette filters out tax navigation when the default currency is not INR and hides the Import action in read-only mode (#29).
  • Standardized browser tab <title> tags across Dashboard, Editor, Sheets, Insights, and Scenarios pages, and aligned svelte-select dropdown and Font Awesome 7 icon sizing with design tokens (#23, #30).
  • Touch targets are 44px on touch screens, and animations are disabled under reduced motion (#23).

Security and dependency upgrades¶

  • Upgraded golang.org/x/net to v0.60.0 (and related golang.org/x modules) in backend and desktop to resolve five reachable HTTP/2 vulnerabilities reported by govulncheck (#27).
  • Upgraded to SvelteKit 3, @sveltejs/adapter-static 4, TypeScript 6, @iconify/tools 5, and svgtofont 6; migrated $lib to #lib subpath imports and $app/stores to $app/state, clearing 40 frontend dependency audit findings (#26).
  • Completed Svelte 5 runes migration by replacing svelte/store, createEventDispatcher, and on: component listeners with rune-based Ref<T>, PersistedState, $state, $effect, and callback props (#30).
  • Upgraded frontend packages to latest major releases including Vitest 5, Biome 2, PDF.js 6, svelte-select 6, svelte-tiny-virtual-list 4, bignumber.js 11, Font Awesome 7, and Playwright 1.65 (#30).

Platform, documentation and developer experience¶

  • Migrated the frontend toolchain from Deno to Bun (package.json, bun.lock, Biome lint, native bun fmt), including CI, Dockerfiles, Dev Container, and dev scripts (#19).
  • Migrated the documentation build pipeline to Zensical with a custom Pygments lexer plugin (paisa_lexers), added CONTRIBUTING.md and contributor guides, and enforced automated documentation validation (scripts/check_docs.py) in CI (#20, #21, #22).
  • Added make modern (go fix) and make audit (bun audit and govulncheck) targets across frontend, backend, and desktop modules (#28).
  • Hardened CI binary downloads with gh release download retries and binary caching, and updated the macOS/Windows desktop smoke test workflow (#24, #30).

0.9.1 (2026-08-27) - @Pratap-kute¶

Security¶

  • Safer file operations: Added path-traversal protection to ledger editor and sheet endpoints so requests cannot escape their configured directories.
  • Modern password storage: Added Argon2id password hashing for user accounts, including transparent migration of existing legacy SHA-256 password hashes after a successful login.
  • HTTP hardening: Added request-size limits, server timeouts, panic recovery, safer SPA routing, and graceful shutdown behavior.
  • Bounded external data: Added response-size limits and context-aware cancellation to HTTP requests and external command execution.

Reliability and data integrity¶

  • Automatic database upgrades: Replaced runtime AutoMigrate calls with serialized, checksummed SQLite migrations. Existing v0.9.0 and v0.9.1 databases are adopted without rebuilding or changing financial data, while incompatible newer schemas and read-only storage now produce actionable startup errors.
  • Atomic configuration writes: Configuration updates now use atomic file replacement and return actionable errors instead of terminating the process.
  • Graceful backend errors: Removed fatal exits from persistence and domain packages so failures propagate through the service and API layers correctly.
  • Concurrency safety: Protected shared accounting, configuration, transaction, prediction, and cache state with synchronization, backed by new concurrency regression tests.
  • Deterministic accounting: Stabilized equivalent postings and balances across ledger implementations while avoiding unnecessary large value copies.
  • Resilient synchronization: Improved model synchronization and save flows so partial failures do not silently leave inconsistent state.

Performance¶

  • Faster database writes: Added indexes for postings and prices and replaced row-by-row persistence with batch inserts where appropriate.
  • Lean lookup paths: Replaced the B-tree-backed lookup path with sorted slices and binary search, and simplified cache hashing and invalidation.
  • Runtime safeguards: Added large-journal, database benchmark, scraper safety, and runtime resilience coverage to prevent regressions.

API and backend architecture¶

  • Typed service boundary: Introduced service, DTO, and mapper layers so HTTP handlers no longer expose persistence models directly.
  • Documented API: Added generated Swagger/OpenAPI documentation, stable operation IDs, handler contract tests, and generated frontend API types.
  • Native Fetch client: Replaced Axios calls with a centralized typed Fetch client, including consistent error responses and automatic ISO date parsing.
  • Clear dependency rules: Added architecture tests that enforce package boundaries and prevent fatal logging from returning to reusable packages.

Frontend architecture and experience¶

  • Feature-oriented modules: Reorganized the frontend into domain, features, shared, and generated subsystems with automated dependency checks and updated parser-generation paths.
  • Centralized state and APIs: Consolidated global state under shared/state, moved financial logic into domain modules, and routed feature API calls through the generated client.
  • Accessible UI primitives: Improved Dialog, Dropdown, Tabs, Tooltip, Command Palette, and related component behavior with expanded accessibility and component tests.
  • Authentication flow: Improved token lifecycle handling, login errors, and account-save feedback.
  • Correct rendering and calculations: Fixed font asset paths, optional posting notes, responsive chart options, overview running totals, commodity repricing, and JSON-schema default item handling.

Testing and CI¶

  • Expanded backend security, API contract, financial, concurrency, and persistence regression suites.
  • Expanded frontend core and component coverage for charts, authentication, imports, navigation, state, and accessible UI behavior.
  • Fixed Go lint findings in posting stabilization and stabilized Vitest thread teardown under Deno-based CI.

Breaking Changes ¶

User's custom import templates used to be stored in Database, which is a bad idea in hindsight. It's being moved to the configuration file. With this change, all the data in paisa.db would be transient and can be deleted and re created from the journal and configuration files without any data loss.

If you have custom template, take a backup before you upgrade and add it again via new version. If you have already upgraded, you can still get the data directly from the db file using the following query sqlite3 paisa.db "select * from templates";
